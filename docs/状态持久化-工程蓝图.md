# 状态持久化工程蓝图（方案甲）

> 版本：v1.0 ｜ 2026-09-05
> 路线：**轻方案**——冻结死引擎（status-system.js），新增状态可写根与命令通道，角色面板显示状态标签。规则权威源保持为「状态列表」世界书条目，引擎只做存储/钳制/显示。
> 前置分析：状态机制三重缺失（无存储/无引擎/无显示），status-system.js 为第三个孤儿模块（零调用方），其内置 28 条状态定义与状态列表.yaml 构成双源。

## 0. 目标与验收标准

| # | 标准 | 验证方式 |
|---|---|---|
| A1 | 主角状态可持久化：AI 经命令区获得/解除状态，存档后跨回合、跨刷新延续 | 命令测试 + 刷新 e2e |
| A2 | 数值护栏：未知状态名拒绝落地；力竭层级钳制 1~3；侵蚀层级钳制 1~2 | 单测 |
| A3 | 角色信息面板显示当前状态标签（负面红/有利绿，力竭显示层级） | e2e + 截图 |
| A4 | 双源消除：status-system.js 移入 legacy 冻结，运行时无引用 | grep 断言 |
| A5 | 回合撤销自动覆盖状态（状态在 gameData 内，随快照回滚） | undo e2e |
| A6 | 敌人状态**不纳入**存储（battle 卡状态栏文本即真相，与蓝图边界一致） | 设计确认 |

**明确不做**：不接状态引擎（方案乙教训）、不做每回合数值记账（状态列表已有此纪律）、不做状态对检定的引擎级修正（优势/劣势由 AI 按状态列表执行，与特质优势同层）。

## 1. 数据模型

### 1.1 gameData 新增根 `conditions`（对象，键=状态名）

```js
conditions: {
  "力竭": { "层级": 2 },
  "失明": true,
  "中毒": { "来源": "感染撕咬" }
}
```

- 键 = 状态名（须在 28 状态白名单内）；值 = `true`（无参状态）或对象（`层级`/`来源` 等可选字段）
- 选对象键控而非数组：AI 操作最直觉（`set 状态.力竭.层级 = 2` / `delete 状态.燃烧`），无需记索引
- 默认值：`{}`（空对象 = 无状态）

### 1.2 命令语法（AI 使用方式）

```
获得状态：set 状态.中毒 = {"来源":"感染撕咬"}
叠加层级：set 状态.力竭.层级 = 2
解除状态：delete 状态.燃烧
```

中文别名（数据同步协议别名表新增）：

| 中文别名 | 规范路径 |
|---|---|
| 状态 / 当前状态 / 负面状态 / 有利状态 | conditions |
| 状态.{状态名} | conditions.{状态名} |

## 2. 引擎改动（command-processor.js，~40 行）

### 2.1 状态白名单（硬编码常量，与状态列表.yaml 同步维护）

```js
var STATUS_WHITELIST = {
  // 负面 22
  '目盲':0,'耳聋':0,'失能':0,'昏迷':0,'麻痹':0,'震慑':0,'石化':0,'中毒':0,'恐慌':0,'魅惑':0,
  '受擒':0,'束缚':0,'倒地':0,'力竭':0,'燃烧':0,'出血':0,'残废':0,'失衡':0,'减速':0,'侵蚀':0,'寒冷':0,'感电':0,
  // 有利 6
  '隐形':1,'加速':1,'耀眼':1,'灵巧':1,'专注':1,'护体':1
};   // 值：0=负面 / 1=有利（面板着色用）
```

### 2.2 normalize 收口（normalizeGameData 内）

```js
var conditions = gd.conditions = gd.conditions || {};
Object.keys(conditions).forEach(function (name) {
    if (!STATUS_WHITELIST.hasOwnProperty(name)) {
        delete conditions[name];                    // 未知状态名拒绝落地
        return;
    }
    var v = conditions[name];
    if (name === '力竭') {
        var lvl = (v && v.层级) ? 规范化整数(v.层级, 1) : 1;
        conditions[name] = { 层级: Math.max(1, Math.min(3, lvl)) };   // 钳制 1~3
    } else if (name === '侵蚀') {
        var st = (v && v.层级) ? 规范化整数(v.层级, 1) : 1;
        conditions[name] = { 层级: Math.max(1, Math.min(2, st)) };   // 钳制 1~2
    } else {
        conditions[name] = (v && typeof v === 'object') ? v : true;
    }
});
```

- 语义规则（非引擎）：力竭达 3 级伴随昏迷、元素交互转化——由状态列表.yaml 指示 AI 执行（AI 写 `set 状态.力竭.层级=3` + `set 状态.昏迷 = true` 两条命令）

## 7. 风险与边界

| 风险 | 对策 |
|---|---|
| AI 忘记落地状态（叙事说中毒但命令区没写） | 状态列表通用规则的强指令 + 实玩观察；未来可做类似 P2 的叙事-状态差分校验（本轮不做） |
| “状态”别名在叙述性 key 中歧义（关系.关系状态 等） | 别名表精确映射 `状态`/`当前状态` 两个短语，`关系状态` 走自身路径不受影响 |
| 28 白名单与状态列表.yaml 漂移 | 白名单注释标注同步来源；状态列表增删状态时两处同步（低频） |
| 敌人状态被误写入 conditions | normalize 白名单不拦“敌人状态对象”，但协议明示敌人状态不入命令区；误写入的敌人名非白名单会被拒 |
