# 实时掷骰 vs 预掷骰池 - 深度对比

> 分析时间：2026-09-02 18:45  
> 对比对象：博德之门3（实时掷骰）vs 灾厄之后（预掷 75 枚）

---

## 📊 核心差异对比表

| 维度 | 实时掷骰（BG3） | 预掷骰池（灾厄） | 影响 |
|------|----------------|-----------------|------|
| **随机性来源** | 每次检定时生成 | 游戏开始时预生成 | 策略性 vs 即时性 |
| **可预测性** | 完全不可预测 | 可查看接下来的骰子 | 运气 vs 策略 |
| **作弊防范** | 可 SL（存档读档） | 无法 SL（骰子已固定） | 难度控制 |
| **心理体验** | 紧张刺激 | 接受命运 | 情绪波动 |
| **实现复杂度** | 简单（Math.random） | 复杂（状态管理） | 开发成本 |

---

## 🎲 1. 实时掷骰（博德之门3 / 传统桌游）

### 工作原理
```javascript
// 每次检定时生成新的随机数
function rollD20() {
  return Math.floor(Math.random() * 20) + 1;
}

// 第一次检定
const roll1 = rollD20(); // 可能是 15

// 第二次检定（完全独立）
const roll2 = rollD20(); // 可能是 3
```

### 优点 ✅

#### 1.1 真实的桌游体验
- 每次掷骰都是**全新的随机事件**
- 符合 DND 桌游的物理感受
- 紧张刺激：不知道下一次会掷出什么

#### 1.2 实现简单
- 一行代码：`Math.random() * 20 + 1`
- 无需状态管理
- 无需持久化存储

#### 1.3 完全公平
- 每个玩家的运气机会相等
- 没有"骰子池用完"的问题
- 长期来看，期望值稳定

### 缺点 ❌

#### 1.4 容易被 SL 作弊
```javascript
// 玩家操作：
1. 存档
2. 尝试困难检定 → 失败（骰值 3）
3. 读档
4. 再次尝试 → 重新掷骰（可能成功）
```

**BG3 的现实：**
- 玩家可以无限 SL 刷出天然 20
- 破坏游戏平衡
- 降低失败的意义

#### 1.5 运气波动大
- 可能连续 10 次失败（虽然概率低）
- 玩家体验差：感觉"被针对"
- BG3 引入"因果骰子"缓解

#### 1.6 无策略性
- 纯粹看运气
- 玩家无法规划
- 无法"留好骰子给关键时刻"

## 🎯 2. 预掷骰池（灾厄之后 / 策略化）

### 工作原理
```javascript
// 游戏开始时预掷 75 枚骰子
const dicePool = {
  d20: [15, 3, 19, 8, 12, 20, 1, 14, ...], // 15 枚
  currentIndex: 0
};

// 第一次检定：使用第 1 枚
const roll1 = dicePool.d20[0]; // 15

// 第二次检定：使用第 2 枚（不可改变）
const roll2 = dicePool.d20[1]; // 3

// 第三次检定：使用第 3 枚
const roll3 = dicePool.d20[2]; // 19
```

### 优点 ✅

#### 2.1 完全防止 SL 作弊
```javascript
// 玩家操作：
1. 存档（骰子池状态也被保存）
2. 尝试检定 → 失败（骰值 3）
3. 读档
4. 再次尝试 → 还是骰值 3（同一枚骰子！）
```

**关键：骰子已经固定，SL 无效！**

#### 2.2 增加策略性
玩家可以**部分规划**：

```javascript
// 玩家可以查看接下来的骰子（调试模式）
peekDice('d20', 5); // [3, 19, 8, 12, 20]

// 策略决策：
// "下一枚是 3（低），我要跳过这次非必要检定"
// "下下枚是 19（高），我要在关键时刻用它"
```

**但灾厄设计：不允许跳选！必须依次使用**

#### 2.3 公平的运气分配
- 每个玩家开局时骰子池已定
- 长期期望值稳定（15 枚 d20 平均值 ≈ 10.5）
- 避免极端运气（连续 20 次天然 1）

#### 2.4 独特的叙事体验
- "命运已定"的宿命感
- "接受你的骰子"的哲学
- 增加游戏深度

### 缺点 ❌

#### 2.5 实现复杂
- 需要状态管理（当前索引）
- 需要持久化（刷新后保持）
- 需要循环逻辑（用完后重复）

#### 2.6 可能感觉"不公平"
```javascript
// 玩家 A 的骰子池：[20, 19, 18, 17, 16, ...]
// 玩家 B 的骰子池：[1, 2, 3, 4, 5, ...]

// 玩家 B：「为什么我的骰子都这么差？！」
```

**但统计学上仍然公平**（期望值相同）

#### 2.7 失去即时紧张感
- 骰子已经固定，部分玩家会觉得"缺少刺激"
- 不如实时掷骰的"命悬一线"感

## 🧠 3. 心理学与游戏体验

### 3.1 实时掷骰的心理

**高峰-低谷的情绪曲线：**
```
检定前：紧张 😰
  ↓
掷骰中：期待 🤞
  ↓
结果出来：
  - 成功 → 狂喜 🎉
  - 失败 → 沮丧 😢
  ↓
下一次检定：重置情绪
```

**特点：**
- 每次都是新的希望
- 失败后还有机会"下次一定"
- 容易上瘾（赌博心理）

### 3.2 预掷骰池的心理

**接受命运的心理曲线：**
```
游戏开始：骰子已定 🎲
  ↓
检定前：查看下一枚（可选）
  ↓
结果出来：
  - 成功 → 满足感（「我早知道」）
  - 失败 → 接受命运（「这是我的骰子」）
  ↓
下一次检定：继续按顺序
```

**特点：**
- "命运已定"的宿命感
- 降低情绪波动（不会突然狂喜或沮丧）
- 鼓励策略思考而非寄希望于运气

## 🎮 4. 游戏设计哲学

### 4.1 实时掷骰的设计理念

**核心：拥抱随机性**
- 运气是游戏的一部分
- 每个瞬间都充满可能性
- 失败也是故事的一部分

**适合：**
- 单人 RPG（BG3、上古卷轴）
- 休闲玩家
- 重视即时反馈的游戏

### 4.2 预掷骰池的设计理念

**核心：驯服随机性**
- 运气不应主导一切
- 玩家应为决策负责
- 增加策略深度

**适合：**
- Roguelike 游戏
- 硬核玩家
- 防止作弊的在线游戏
- 强调"接受命运"的叙事

## 🔍 5. 具体场景对比

### 场景 1：关键剧情检定

**实时掷骰（BG3）：**
```
玩家：「我要说服守卫放我进城」
系统：「魅力检定 DC 15」
掷骰：d20 = 8，魅力调整值 +3，总值 11
结果：失败
玩家心理：「F5 大法！」（SL 重来）
```

**预掷骰池（灾厄）：**
```
玩家：「我要说服守卫」
系统：「从骰子池取用第 7 枚 d20」
骰值：3（已固定）
魅力调整值 +3，总值 6
结果：失败
玩家心理：「这是我的命运，SL 也没用，只能想别的办法」
```

### 场景 2：连续战斗检定

**实时掷骰（BG3）：**
```
第 1 次攻击：d20 = 15（命中）
第 2 次攻击：d20 = 2（未命中）
第 3 次攻击：d20 = 18（命中）
玩家：「运气不错！」
```

**预掷骰池（灾厄）：**
```
第 1 次攻击：骰子池第 1 枚 = 15（命中）
第 2 次攻击：骰子池第 2 枚 = 2（未命中）
第 3 次攻击：骰子池第 3 枚 = 18（命中）
玩家：「我的骰子池前 3 枚是 [15, 2, 18]，还不错」
```

### 场景 3：SL 作弊尝试

**实时掷骰（BG3）：**
```
存档 → 检定失败 → 读档 → 重新掷骰（可能成功）
结果：作弊成功！
```

**预掷骰池（灾厄）：**
```
存档 → 检定失败 → 读档 → 还是同一枚骰子（必然失败）
结果：作弊无效！
```

## 📐 6. 数学与统计

### 6.1 期望值对比

**实时掷骰：**
```
每次独立：E[d20] = 10.5
100 次检定期望：1050
```

**预掷骰池（15 枚 d20）：**
```
第一轮（1-15 次）：E[总和] = 157.5
第二轮（16-30 次）：E[总和] = 157.5（循环使用）
100 次检定期望：1050
```

**结论：长期期望值相同！**

### 6.2 方差对比

**实时掷骰：**
- 高方差：可能连续 10 次天然 1（虽然概率 5^-10）
- 短期波动大

**预掷骰池：**
- 低方差：75 枚骰子的分布更平滑
- 短期波动小（平均值更接近 10.5）

## 🎯 7. 灾厄之后的设计选择

### 为什么选择预掷骰池？

#### 7.1 防止作弊（核心原因）
- 独立前端 + SillyTavern 模式容易被 SL
- 预掷骰池让 SL 无意义

#### 7.2 增加策略性
- 玩家可以（在某些模式下）查看接下来的骰子
- 鼓励"接受命运"而非"刷运气"

#### 7.3 叙事一致性
- "废土世界，命运已定"的主题
- "骰子是你的命运，接受它"

#### 7.4 技术实现
- 更容易实现可复现的游戏（录像/回放）
- 更容易调试（骰子池固定）

## 🚀 8. 混合方案（可选扩展）

### 8.1 半透明骰子池
```javascript
// 玩家可以查看"下一枚"（仅下一枚）
const nextDice = peekDice('d20', 1); // [12]

// 决策：
if (nextDice[0] < 10) {
  // "下一枚很低，我要避免非必要检定"
}
```

**平衡：给玩家部分信息，但不能完全规划**

### 8.2 命运点重掷机制（已实现）
```javascript
// 允许花费命运点"跳过"当前骰子
useFatePoint(); // 消耗 1 点命运点
const newRoll = getD20(); // 取用下一枚
```

**平衡：给玩家"改变命运"的机会，但有限制**

### 8.3 因果骰子（BG3 风格）
```javascript
// 追踪连续失败次数
if (consecutiveFailures >= 3) {
  // 下一枚骰子 +5（暗中提升）
  roll = Math.min(20, roll + 5);
}
```

**平衡：减少挫败感，但保持骰子池的核心机制**

## 📊 9. 最终对比总结

| 方面 | 实时掷骰 | 预掷骰池 | 优势方 |
|------|---------|---------|--------|
| **作弊防范** | ❌ 易被 SL | ✅ 完全防范 | 预掷 |
| **即时刺激** | ✅ 紧张刺激 | ❌ 平淡 | 实时 |
| **策略深度** | ❌ 纯运气 | ✅ 可规划 | 预掷 |
| **实现难度** | ✅ 简单 | ❌ 复杂 | 实时 |
| **公平性** | ✅ 公平 | ✅ 公平 | 平局 |
| **叙事深度** | 一般 | ✅ 宿命感 | 预掷 |
| **玩家接受度** | ✅ 熟悉 | ⚠️ 需适应 | 实时 |

## 💡 10. 建议

### 对于灾厄之后项目

**✅ 保持预掷骰池设计！**

理由：
1. **防止作弊**是硬需求（独立前端易被操控）
2. **策略性**符合废土主题（资源稀缺、谨慎决策）
3. **叙事一致**（命运已定、接受骰子）
4. **已实现**，成本沉没

### 可选增强

1. **新手模式**：允许查看下 1 枚骰子
2. **因果骰子**：连续失败后暗中 +5
3. **命运点系统**：已实现，继续优化

## 🎮 11. 玩家引导

### 如何让玩家接受预掷骰池？

#### 教程文案示例

```
🎲 骰子池机制

在《灾厄之后》中，你的命运在冒险开始时已经确定。

游戏开始时，系统已为你预掷了 75 枚骰子。
每次检定、战斗、锻造，都会依次使用这些骰子。

⚠️ 重要：
- 你不能"刷新"骰子来获得更好的结果

- 这就是你的命运，接受它，利用它

💡 策略提示：
- 使用"命运点"在关键时刻重骰
- 合理规划，避免浪费在非必要检定上
- 失败也是故事的一部分

这不是运气游戏，这是命运游戏。
```
