# 战斗引擎加固工程蓝图

> 版本：v1.0 ｜ 2026-09-05
> 路线前提：**维持"AI 叙事战斗"路线**（不接管计算、不做战术引擎），本地只做三件事——**冻结死引擎、把战斗状态可见、对战斗数学校验警示**。

## 0. 目标与验收标准

| # | 标准 | 验证方式 |
|---|---|---|
| A1 | 双引擎归一：运行时不存在 combat-system/creature-system 加载路径，双状态源暗雷消除 | 模块加载清单 + grep 断言 |
| A2 | 生物数据单一事实源：世界书 23 生物 yaml 为唯一权威，JS 重复模板不再被引用 | grep + 文档标注 |
| A3 | 战斗状态可见：战斗中侧栏「战斗信息」实时显示回合/敌人 HP/交战距离/状态；战斗结束显示结果 | 浏览器 e2e + DOM 断言 |
| A4 | 数学校验警示：伤害卡数字与 HP 命令扣减不一致、耐久漏扣、HP 越界时，叙事流出现可读警示行 | 单测（构造不一致样例） |
| A5 | 长回合收敛：战斗超 8 回合触发收敛提示（叙事层） | yaml 规则 + e2e |
| A6 | 回合撤销后战斗面板与叙事流一致（不残留已撤销回合的战斗状态） | undo e2e |

**明确不做**：不本地重算命中/伤害、不把敌人 HP 纳入 gameData（命令面膨胀）、不做战术网格——AI 保持战斗叙事唯一权威。

## 1. 现状盘点

### 1.1 活引擎链路（保持不动）

```
结算协议 B 节（流程编排）

```

### 1.2 死引擎（本蓝图处置对象）

- `module/combat-system.js`（535 行）：startCombat/playerAttack/nextTurn/rollInitiative/playerFlee——模块外**零调用方**

### 1.3 现有解析锚点

- `<battle>` 卡标准行格式（渲染器已识别）：`战斗开始/结束横幅`、`先攻顺序：`、`交战距离：`、`第 N 回合`、`【行动者】`、`行动：`、`[伤害 N]`、`[骰值]`、`✓命中`、`✗未命中`、`💥重击`、`胜利/战败/逃脱`

## 3. P1 战斗追踪器（A3/A6，新模块 `module/battle-tracker.js`，约 200 行）

### 3.1 数据模型（纯内存，不持久化——战斗是叙事局部事件）

```js
battleState = {
  active: true,
  round: 3,
  distance: '10 米 -> 5 米',
  actors: [                       // 主角 + 各敌人
    { name: '凛夏', side: 'player', hp: {cur: 72, max: 100}, mp: {cur:40, max:40}, statuses: ['中毒'] },
    { name: '裂隙犬', side: 'enemy', hp: {cur: 12, max: 24}, statuses: [] }
  ],
  result: null                    // '胜利' | '战败' | '逃脱'
}
```

### 3.2 解析器：`battleTracker.ingest(battleCardText, gameData)`

- 输入：**最新一张 `<battle>` 卡全文**（response-parser 已保留卡块；新增 `getLatestBattleCard()` 导出）
- 解析规则（全部基于 §1.3 锚点）：
  - `战斗开始` → reset state，actors = [主角（HP 取自 gameData.hp）]
  - `【名称】 HP a/b` 敌人面板行 → upsert actor；新名称 → 新增 enemy actor
  - 主角 HP 双显行 → 更新 player.hp（cur/max）
  - `第 N 回合` → round；`交战距离：` → distance；`状态` 词（中毒/燃烧/出血…按「状态列表」名词表）→ actor.statuses
  - `胜利|战败|逃脱` → active=false, result
- 主角 HP 以命令引擎落地值为准（卡面数字仅用于敌人）——与 P2 校验互补

### 3.3 面板渲染：`battleTracker.renderPanel()`

- 目标：设置页之外右侧的「◈ 战斗信息」面板（index.html:2081，现为静态"当前无战斗"）
- 战斗中显示：`第 3 回合 ｜ 距离 10→5 米` + 敌人 HP 条（迷你条，复用 hp-bar 样式）+ 主角/敌人状态标签
- 非战斗显示：`当前无战斗`（现状）或最近一场结果（`上场：胜利`，保留至下一次进入游戏）

### 3.4 撤销一致性（A6）

- 回合撤销回滚叙事页后，**战斗状态可能与叙事不符**
- 方案：`undoLastTurn()` 末尾调用 `battleTracker.rebuildFromNarrative()`——从叙事 DOM 中取最后一张 `.battle-card` 的文本重新 ingest；无 battle 卡则 state 清空回"当前无战斗"
- 无需把 battleState 纳入撤销快照（叙事流本身就是战斗状态的持久层，DOM 即真相）

### 3.5 接线点

| 位置 | 调用 |
|---|---|
| index.html send 流程（responseParser.run 之后） | `battleTracker.ingest(getLatestBattleCard())` + `renderPanel()` |
| undoLastTurn 尾部 | `rebuildFromNarrative()` + `renderPanel()` |
| script 加载 | `<script src="module/battle-tracker.js"></script>`（story-engine 之后） |

## 4. P2 战斗数学校验层（A4，挂 response-parser 与命令应用之间）

### 4.1 新函数：`battleMathCheck(battleCardText, commands, gdBefore)`（置于 index.html send 流程，约 120 行）

逐条规则，输出 `{warnings: string[], stats: {...}}`，**只警示不静默改值**（AI 是叙事权威）：

| # | 规则 | 检查逻辑 | 警示示例 |
|---|---|---|---|
| R1 | 伤害-HP 一致 | 卡内所有 `[伤害 N]`（作用于主角，即敌人回合块内）合计 vs 同轮 `<命令>` 中 `add HP` 负值合计；差值 ≠ 0 → 警示 | `⚠ 伤害结算不一致：卡面合计 -14，HP 命令 -10（差 4）` |
| R2 | 耐久-命中一致 | 主角命中行（✓）次数 vs `装备.主手.耐久` 负命令次数；漏扣 → 提醒（含补发建议命令） | `⚠ 疑似漏扣武器耐久：命中 3 次，耐久命令 2 次` |
| R3 | HP 越界哨兵 | 命令执行后 HP ≤ 0 而卡面无死亡/败北字样 → 提醒 AI 补结算 | `⚠ 主角 HP 已归零但叙事未结算倒下` |
| R4 | 重击耐久 | 💥行外的天然 1（✗ 且含"天然1/大失败"）未伴随耐久 -5 命令 → 提醒 | 同 R2 格式 |

- 命令与卡面的**行动者归属**按回合块切分（`【行动者】`行分段），敌人对主角的伤害只统计敌人回合段
- 警示以 `⚠ sys-line` 追加到叙事流末尾（复用现有 error-strip 样式，弱化为警示色），不中断游戏
- 本层**不含**敌人 HP 校验（敌人 HP 只存在于卡面叙事，无命令可对照——这与"不把敌人纳入 gameData"的边界一致）

### 4.2 协议配套（输出格式.yaml 战斗节追加一句）

> 伤害与 HP 扣减必须严格一致：每个 `[伤害 N]` 落地时必须同步给出等额 HP 命令；命中后武器耐久 -1 不得遗漏。

## 5. P3 长回合收敛（A5，纯世界书规则）

战斗规则.yaml 追加一节：

```
## 回合收敛

- 常规战斗以 3~6 回合为宜；第 8 回合起必须主动收敛：敌人士气崩溃/撤退/求饶，或环境事件介入，不得无限拉锯
- 敌人 HP 低而战斗超 6 回合时，优先按生物条目习性结算脱离（多数野外生物不恋战）
```

（零代码：AI 层规则，收敛叙事本身由模型执行。）

## 7. 风险与边界

| 风险 | 对策 |
|---|---|
| AI 输出的卡面格式漂移（漏 HP 双显、行动者块格式变体） | 解析器按宽松正则 + 未知行忽略；解析失败时面板回退"当前无战斗"，不报错打扰 |
| R1 归属切分在混乱回合块下误报 | 仅统计能明确归属「敌人回合段」的伤害行；归属不明的跳过（宁漏报不误报） |
| 警示行打扰叙事 | 警示行用弱化样式且仅在真正不一致时出现；不自动改值 |
| 冻结后有人误接线 legacy | 冻结头注释 + PROJECT-STATUS 已知问题表更新 |

## 8. 明确不做的事

- 不本地接管命中/伤害/先攻计算（AI 叙事权威不动摇）
- 不把敌人实体纳入 gameData/命令面（面板数据从卡面解析）
- 不做战术网格、动作经济、职业系统（前次结论维持）
- 不动 check-system/dice-pool（它们是活引擎的组成部分，锻造/炼金/开局包依赖）
