# 记忆系统 2.0 设计方案（v2 修订）

> 目标：**1000 层不混淆、每层可考、不依赖向量**。向量召回降级为可选增强。
> v2 变更：压缩结构改为**滚动合并三级制**（纪事→卷宗→典章），近期颗粒度 20 层，总预算恒定；明确"层=回合"。

## 一、设计原则

1. **有损但可考**：逐字记住 1000 层不可行（≈7 万 token），但"每一层发生了什么"必须永远可查——一行索引保底，按需展开。
2. **越近越细，越远越浓**：记忆分辨率随距离衰减（20 层→100 层→300 层颗粒度），模拟自然遗忘曲线，但主线因果永远在场。
3. **预算恒定**：常驻注入量不随楼层数线性增长——靠滚动合并，而不是靠"只保留最近 N 篇"。
4. **数字不走记忆**：需要精确的事实由命令引擎 gameData 承载，AI 永远不需要"记住"数值。
5. **单调用架构**：不增加每回合 LLM 调用次数；压缩与提取都挂在已有的批次时机上。

## 二、"层"的定义

**一层 = 一回合 = 玩家一次输入 + AI 一次完整回复**（含该回复内的检定/战斗/`<SUMMARY>` 块）。

- 每收到一次带 `<SUMMARY>` 的回复，`vecNextFloor()` +1，该回复的所有摘要共用同一楼层号。
- 回合撤销回滚该层的全部记忆记录；楼层号不回收（空洞无影响，天然标记撤销史）。

## 三、记忆结构：一条查询线 + 一条常驻线

```
【查询线】编年史：每层一行索引，平时在库里，关键词命中才展开   → 管"第X层发生了什么"
【常驻线】滚动合并三级：纪事 → 卷宗 → 典章，全部常驻           → 管"故事到目前的因果"
```

### 3.1 查询线：编年史（新增，零 LLM 成本）

- **每层一行**，本地从纪要拼接（时间字段直接读该层命令结算后的 `gameTime`，同一天内可省略日期）：
  ```
  第87层｜300年11月14日 14:30·铁矿镇｜初遇莉娅，接下护送任务
  ```
- 存储：`calamity-vecmem` v3 新增 `chronicle` store（主键=楼层号），1000 行 ≈ 3 万字 ≈ 2 万 token，**不全量注入**。
- 注入：常驻最近 100 行；更早的行做关键词索引（NPC 名/地点名/任务名），当前回合意图文本命中时展开对应楼层的**纪要全文**。
- 嵌入服务开启时向量召回优先、编年史命中合并；关闭时词法检索自动接管。

### 3.2 常驻线：滚动合并三级（核心变更）

压缩不再是"每固定 N 层出一篇、越攒越多"，而是**每级攒满就向上一级合并，本身只保留最近几篇**：

```
纪事  每 20 层压缩一篇，≤150 字。只保留最近 5 篇（覆盖最近 100 层）。
卷宗  每攒满 5 篇纪事合并成 1 篇卷宗（= 100 层），≤400 字。只保留最近 3 篇（再往前 300 层）。
典章  每攒满 3 篇卷宗合并成 1 篇典章（= 300 层），≤600 字。全部常驻（数量增长极慢）。
```

**1000 层时的常驻账**：

| 级 | 在场数量 | 字数 |
|---|---|---|
| 纪事 | 5 篇（第 901~1000 层，20 层颗粒度） | 750 |
| 卷宗 | 3 篇（第 601~900 层，100 层颗粒度） | 1200 |
| 典章 | 3 篇（第 1~600 层，300 层颗粒度） | 1800 |
| 编年史尾 | 最近 100 行 | 3000 |
| **常驻合计** | | **≈6800 字 ≈ 4800 token** |

**2000 层时**：典章 6~7 篇（+4200 字），其余不变 ≈ 7800 token——增长是**对数级**的。若要彻底封顶，加一条终级规则：典章满 4 篇时两两合并为纪元史（可不设，等 2000+ 层实测再说）。

**分辨率结构**（这是本方案对"20 层"诉求的回应）：
- 最近 100 层：AI 记得每 20 层一段的具体事件；
- 100~300 层前：记得每 100 层一段的主线走向；
- 300 层以前：记得每 300 层一段的时代因果；
- 任何一层：编年史索引永远在，关键词一碰就展开成纪要全文。

### 3.3 压缩提示词（统一采用 World 总述规范）

三级共用同一套提示词规范，要点：
- 产出"可脱离原文独立使用的阶段纪事"，写清关键行动如何引出后果、人物为何改变目标或立场；
- **已完成/取消/失败/作废的事项与建立的事项同等重要**，禁止只留开端不留结局（防"悬而未决"线索堆积成混淆源）；
- 禁止"局势变化了""经历了一系列事件"等空壳句；保留具体人物、动作、对象与结果；
- 合并同级多篇时允许重复信息归并与过程压缩，但不得把具体事件抽象成空泛趋势；
- 怀疑、误解、谣言保持人物认知表述，不得升级为世界事实。

## 四、防混淆专用层（P1）

### 4.1 人物主观记忆（借鉴 World）

- 记录"某个 NPC 记得/相信/怀疑/误解什么"：`{holder, memory≤50字, time绝对故事时间, known_by知情者, 强度保留}`。
- 提取时机：**挂在纪事压缩时批量回溯**（每 20 层一次，每阶段每人 ≤3 条、整批 ≤10 条）——主观记忆是长期印象，20 层粒度恰好，且不占每回合主调用。

### 4.2 实体台账（借鉴 World）

- 记录 gameData 表达不了的世界事实：组织/物品/能力/地点的当前态 + 变更史 + aliases。
- 走命令引擎新增 `[实体更新]` 命令维护；权威数值仍归 gameData。
- 注入：当前场景相关实体的当前态 + 最近 2 条 history。

## 五、每回合注入管线（固定顺序）

| # | 块 | 来源 | 1000 层时 |
|---|---|---|---|
| 1 | 状态栏/面板数据 | gameData（权威） | 已有 |
| 2 | 世界书常驻条目 | worldbook | 已有 |
| 3 | 典章（全部） | 常驻线 L3 | ~1800 字 |
| 4 | 卷宗（最近 3 篇） | 常驻线 L2 | ~1200 字 |
| 5 | 纪事（最近 5 篇） | 常驻线 L1 | ~750 字 |
| 6 | 纪要窗口（近 20 条全文） | 纪要层 | ~1600 字 |
| 7 | 编年史尾部（近 100 行） | 查询线 | ~3000 字 |
| 8 | 【相关记忆】检索展开 | 向量召回 或 编年史词法命中 | ~600 字 |
| 9 | 【人物记忆】登场 NPC | 主观记忆层 | ~500 字 |
| 10 | 【实体台账】场景相关 | 台账 | ~400 字 |
| 11 | 最近 8 层正文 | 逐字上下文 | 已有 |

**新增常驻 ≈ 4800 token，2000 层时 ≈ 7800，对数增长。**

可选点缀：指数衰减随机抽样（World 的 `exponentialMemorySample`，约 20 行代码），每回合 15% 概率额外唤起 1 条远期纪要，模拟"偶然想起"，不承担底线职责。

## 六、防混淆机制清单

| 混淆类型 | 对策 |
|---|---|
| 数字/持有物矛盾 | 命令引擎 gameData 权威 + 状态栏回传（已有） |
| 时间线漂移 | 纪要/纪事强制绝对时间锚点（`300年11月14日`，数字纪年同 gameTime） |
| 远期主线遗忘 | 典章/卷宗常驻（滚动合并保证永不清零） |
| 中期剧情模糊 | 纪事 20 层颗粒度 + 编年史 100 行尾窗 |
| 具体某层查不到 | 编年史全量索引 + 关键词展开 |
| 线索悬而未决堆积 | 压缩提示词强制记录已完结/已失败事项 |
| AI 全知 | 主观记忆 known_by 知情者机制 |
| 同一实体多个名字 | 台账 aliases 归并 + 提示词要求沿用规范名 |
| 空壳总结稀释上下文 | 提示词禁止抽象概括，要求具体人物/动作/结果 |

## 七、统一记忆系统 + 副 API（v2.2 修订）

**只有一个记忆系统**，向量记忆是其内部的可选模块（默认关闭）：

- **核心（常启）**：纪要库 + 编年史 + 滚动合并常驻线 + 词法检索 + 注入管线。常驻线与向量无关，永远在场。
- **向量模块（可选开启）**：开启后摘要向量化入库，检索展开块变为"向量召回 ∪ 词法命中"（按楼层去重）；关闭则词法独挑，管线其余不变。L2 事件层与 arc 压缩不迁移——分别由账本套件与滚动合并替代。
- **副 API**：记忆系统的全部 LLM 调用（三级压缩、主观记忆提取、台账维护）走独立副 API 渠道（独立 url/key/model，未配置时跟随主 API），嵌入调用沿用独立嵌入配置。主对话 API 只负责叙事，互不干扰、可指派廉价模型。

工程细节见《记忆系统2.0-工程蓝图.md》（v2.2）。

## 八、一致性保障

- **撤销**：undo 快照增加 `chronicleFloors`、`storyIds`、`subjectiveIds`、`ledgerIds`，按 id 集合差量回滚（与现有 vecIds/l2Ids 同模式）。压缩产物被撤销跨及时，按"受影响楼层号"重算：纪事若含被撤销楼层则标记待重压，下次压缩时机自动重做。
- **hash 校验**（借鉴 World）：编年史行与纪事存储来源楼层 hash，编辑/重掷后失效内容停止注入并标记待修复，避免信息洞。

## 九、实施分期

- **P0（纯文本记忆闭环）**：纪要楼层锚点协议 → 编年史层+词法注入 → 滚动合并三级压缩 → 撤销联动。完成后即达成 1000 层目标。
- **P1（防混淆增强）**：实体台账命令 → 主观记忆批量提取 → 记忆库查看器页签。
- **P2（体验）**：指数衰减抽样点缀 → hash 校验修复流程 → 检索命中高亮。
