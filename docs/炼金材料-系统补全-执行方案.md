## T2. 收购价接口

### 目标
新增 `materialSystem.getSellPrice(materialName, options)`，按"公会收购 50%" + 好感度折扣 + 偏远折扣计算卖价。

### 涉及文件
- `module/material-system.js`

### 涉及修改

在 `MaterialSystem` 类中新增方法：

```javascript
/**
 * 获取材料卖价（玩家卖给公会/NPC）
 * @param {string} materialName - 材料名
 * @param {Object} options - { remote?: bool, relationship?: '冷淡'|'友好'|'信任'|'亲密' }
 * @returns {number} 卖价（金）
 */
getSellPrice(materialName, options = {}) {
  const material = MATERIALS[materialName];
  if (!material) return 0;

  const basePrice = material.price;
  const buybackRate = 0.5;  // 公会收购按 50%（与材料总纲对齐）

  let price = basePrice * buybackRate;

  if (options.remote) {
    price *= this.priceModifiers.remote;  // 偏远 ×1.35
  }

  if (options.relationship) {
    price *= this.priceModifiers.relationship[options.relationship] || 1.0;
  }

  return Math.ceil(price * 100) / 100;
}
```

并把 `priceModifiers.remote` 和 `priceModifiers.relationship` 抽出来（若当前是类内私有属性，需提升为可读常量或保留调用方式）。

### 数据契约
```
getSellPrice('草药', { relationship: '友好' }) === 0.1
// 0.2 × 0.5 = 0.1
```

### 验证
- 加 **7k** 断言：getSellPrice('草药', {}) === 0.1
- 加 **7l** 断言：getSellPrice('草药', { relationship: '信任' }) === 0.09（0.2 × 0.5 × 0.9）
- 加 **7m** 断言：未知材料 → 返回 0

### 工作量
**0.5-1 小时**

## T3. 自炼真实成本接口

### 目标
让 `brewPotion()` 用「材料真实价格之和」算自炼成本，而不是「成品基准价 ÷ 2」。

### 涉及文件
- `module/material-system.js`
- `module/alchemy-system.js`（协调点）

### 涉及修改

**material-system.js** 新增：

```javascript
/**
 * 计算自炼真实材料成本（材料基础价之和，不套 ÷ 2）
 * 用于取代 calculateAlchemyCost() 的「按成品价 ÷ 2」逻辑
 * @param {Object} requiredMaterials - { 材料名: 数量 }
 * @returns {number} 真实材料成本（金）
 */
calculateRealMaterialCost(requiredMaterials) {
  let total = 0;
  for (const [name, amount] of Object.entries(requiredMaterials)) {
    const material = MATERIALS[name];
    if (!material) continue;  // 缺失材料按 0 价（强迫补登记）
    total += material.price * amount;
  }
  return Math.ceil(total * 100) / 100;
}
```

**alchemy-system.js** 修改 brewPotion()：

```javascript
// 旧：
const materialCost = this.calculateMaterialCost(recipe.basePrice);

// 新：
const materialCost = materialSystem.calculateRealMaterialCost(recipe.materials);
```

并保留 `calculateMaterialCost()` 作为 legacy 入口（暂时不删，避免破坏其他可能调用方）。

### 经济循环验证

| 配方 | 旧成本（基准价÷2） | 新成本（材料价之和） | 差额 |
|------|-------------------|-------------------|------|
| 治疗药水 | 1 金 | 0.5 金（草药 0.4 + 净化苔藓 0.5 - 净化苔藓只算 1 份）= 0.4 金 | -0.6 金 |
| 强效治疗药水 | 12.5 金 | 草药×5=1 + 魔力精华=4 + 清水=0（未登记）≈ 5 金 | -7.5 金 |
| 传奇法力药水 | 100 金 | 能量晶簇×2=400 + 魔力精华=4 = 404 金 | +304 金（可能过贵） |

**风险**：新成本对部分配方**显著高于基准价÷2**，会让自炼"不划算"。需要：
- 接受这个经济现实（自炼应比买便宜，差额是「自炼风险 + 时间」的溢价）
- 或调整材料价（让 T1 的预估更保守）
- 或在 `brewPotion` 中**双口径记账**：`economicCost = materialCost`、`referenceCost = recipe.basePrice/2`，UI 显示 economicCost，逻辑判定用 referenceCost

**建议做法**：双口径记账，UI 透明显示两个数。

### 验证
- 加 **7n** 断言：calculateRealMaterialCost({ '草药': 2 }) === 0.4
- 加 **7o** 断言：brewPotion() 返回的 materialCost 字段来自 calculateRealMaterialCost

### 工作量
**1-2 小时**（含双口径设计 + UI 协调）

## T4. 采集接口

### 目标
新增 `materialSystem.gatherMaterials(location, character, options)`：玩家在地理/生物区域采集，随机获得对应材料。

### 涉及文件
- `module/material-system.js`
- 新增数据：`module/gathering-table.js`（或内嵌在 material-system.js）

### 数据结构

每个地理/生物条目需要一张「采集表」：

```javascript
// data-source/世界书/地理/灰烬森林.yaml 内新增或外挂
gatheringTable:
  materials:
    - { name: '草药',           weight: 50, amount: '1d3' }
    - { name: '净化苔藓',       weight: 30, amount: '1d2' }
    - { name: '晶壳蝎毒液',     weight: 5,  amount: '1'    }
    - { name: '灾厄金属',       weight: 1,  amount: '1'    }  // 稀有掉落
  cooldownMinutes: 60  // 同一地点采集冷却（游戏内时间）
```

### 涉及修改

**material-system.js** 新增：

```javascript
/**
 * 玩家在指定地点采集
 * @param {string} locationKey - 地理 key（如 '地理/灰烬森林'）
 * @param {Object} character - 角色
 * @param {Object} options - { skillCheck?: bool, attribute?: string, dc?: number }
 * @returns {Object} { success, materials: [{name, amount}], narrative }
 */
gatherMaterials(locationKey, character, options = {}) {
  const table = GATHERING_TABLES[locationKey];
  if (!table) {
    return { success: false, error: '未知地点' };
  }

  // 冷却检查（读 gameTime.lastGatherAt）
  if (this.isGatherOnCooldown(character, locationKey, table.cooldownMinutes)) {
    return { success: false, error: '采集点尚未刷新' };
  }

  // 可选：技能检定（力量草需要感知检定 vs DC12）
  if (options.skillCheck) {
    const check = performCheck({
      attribute: options.attribute,
      gameState: character,
      dc: options.dc || 12,
      description: '采集检定'
    });
    if (check.total < options.dc) {
      return { success: false, checkResult: check, message: '采集失败' };
    }
  }

  // 按权重掷出 1~3 种材料
  const rolled = this.rollGathering(table.materials, options.amount || 3);

  // 加入背包
  this.addMaterials(character, rolled);

  // 记录冷却
  this.recordGather(character, locationKey);

  return { success: true, materials: rolled, location: locationKey };
}
```

### 涉及世界书条目

需要给「地理」5 个区域 + 「生物」高掉率生物（如晶壳蝎 → 晶壳蝎毒液）都加 `gatheringTable` 字段。

**估算工作量**：5 区域 × 30 分钟 ≈ 2.5 小时；23 生物中可能涉及的（如毒物类生物） × 15 分钟 ≈ 1-2 小时。**总计 3-5 小时**。

- 加 **7q** 断言：冷却时间内二次调用 → 返回 cooldown 错误
